# Lite rules — the mandatory QC rules, one line each

Loaded with SKILL.md, kept for the whole run. Every rule has ONE home in the engine (`engine/references/…`, the vendored Full text);
open that file only when this line is not enough to act. Lite drops the *process* around the rules, never the rules.

| # | Rule | Enforced by | Full home |
|---|---|---|---|
| 1 | **POM is mandatory.** No raw locator, navigation, `evaluate`, keyboard driving or chained locator in a spec; flows live in page objects; reuse the project's POMs / helpers / `api/` / `db/` objects first (inventory before a new page class). Shared UI (readiness wait, shell, toast) lives once in a base / component class, never copied per page. | A · `lite:pom` | `code-generation.md` `<pom_mandatory>`, `<automation_inventory>` · `code-craft.md` §1-5 |
| 2 | **Approved-TC traceability.** Automate from the ORIGINAL approved document. Every test title starts `[TC-ID]`, every `describe` carries its `REQ-…`; each in-scope TC maps to ≥ 1 test or has a written exclusion (manual / blocked / not a candidate). IDs are never invented. Mapping is not execution success. Read from the **resolved** titles (`--list`): variants are a loop over a literal list, one `[TC-ID]` per resolved title. A setup / teardown **journey** (annotation `journey`, listed by `lite journey`) carries no TC-ID and is never a result. | A · `lite:traceability` | `code-generation.md` `<spec_writing>` · `automation-rules.md` §6 |
| 3 | **Meaningful assertions.** Every test asserts its required outcome from the TC's *Expected Result*; no placeholder, empty body or visibility-only check where a value is required. Weak ones are repaired, never left. | A · `lite:assertions` | `automation-rules.md` §2 |
| 4 | **No guessed selectors.** Every selector is confirmed in app source or an existing page object; a live look only for an AMBIGUOUS case. Only a safe `data-testid` may be added to product code. | review + A | `code-generation.md` `<selector_resolution>` |
| 5 | **Source of truth.** Only an approved requirement / clarification defines an expected result. An unresolved wording is coded as the recommended reading, tagged `@unverified-assumption`, listed in `unverified_assumptions[]`, and such a test is **never** `app_bug`. | B · `lite:failure-evidence` | `code-generation.md` `<source_of_truth>` · `open-questions.md` |
| 6 | **Smoke gate 30 %.** Fail % over PASS + FAIL of smoke; > 30 % or NO VERDICT ⇒ positive / negative never start (`lite stage` refuses). What did not execute is `NOT_RUN` with its reason; SKIP / BLOCKED / NOT_RUN are never PASS. | `lite stage` · B · `lite:tc-status-coverage` | `execution.md` `<staged_execution>` |
| 7 | **Test-data safety.** Reuse valid data first. A TC that creates / modifies / deletes data needs the tester's per-TC yes (`--allow-data-changes` → `lite init-run` / `lite consent` write the record; never hand-written), a `test` / `staging` environment class, run-owned records only (`uniqueName()` / `runPrefix()`). **Every data change goes through the ledger (`helpers/data-ledger.ts`) — `prerequest/` test-support calls (clock, reset, outbox) and data-changing page-object actions included** (template `assets/templates/prerequest-ledger.ts`); no ledger ⇒ check 53 unresolved. **The op names the owner:** the first clock set / seed reset / submitted record is `create` (`createOrModify`), a later change inside it `modify` / `remove` of that run-created resource (`inRunData`), a change to data the run did not create `modify-external` — which check 53 refuses whatever the consent. Never touch an unrelated record. | A (ledger warning · **ledger ownership FAIL**) · B · `lite:results-integrity` | `api-db.md` `<data_changes_gate>` · `test-data-preparation.md` |
| 8 | **Workers.** Policy: **max 5** (`--max-workers`, never above 5); **at least 2 when `parallel-plan` proves ≥ 2 independent TCs** (no shared test data / state between them), up to the number of independent units; one worker when they share data, an account, a DB row or a rate limit. A stricter project / environment limit (`machineMaxWorkers`, `execution.maxWorkers`, rate limits) wins. **No host-memory gate:** low free memory never blocks or waits — a serial stage runs without the capacity ledger, a parallel stage checks free memory once and drops to fewer workers or to serial. Only Full's floor (a machine that cannot hold one browser) still refuses. | `lite stage` | `run-plan-and-config.md` `<parallel_readiness>` |
| 9 | **Healing.** Fix automation-code defects only, ≤ 2 attempts per test, root cause from evidence. Never lower or broaden an assertion, never edit an expected value to match wrong behaviour, never skip / retry / lengthen a timeout to hide a failure, never change product behaviour. An app defect is reported (`app_bug`) with its original expected outcome. Interference suspected ⇒ the isolation re-run (run-stage does it) decides. A "click again when the state did not change" heal asserts the expected state after the retry (a dead control still FAILs) and its row says `retry_used: true`. Heal Log row per fix, with `cause_class`. | B · `lite:failure-evidence` | `execution.md` `<first_run>` · `automation-rules.md` §5 |
| 10 | **Impacted re-run only.** Collect every heal of the stages first, then `lite rerun-select` once; it widens by itself when a shared POM / fixture / helper / config changed. Refresh `checkpoint-a` on the changed files first. Burn-in ×3 (`--burn-in`) of the healed `timing` / `flaky` / `race` TCs BEFORE the widened set; **at most one widened pass per heal round**. No full re-run without a selection that asks for it. | `lite rerun-select` · `lite stage --burn-in` | `final-run.md` `<second_run>` |
| 11 | **Evidence.** One assertion-point image per UI test (`captureEvidence`), one redacted record per API / DB test; screenshots default **failed only**. Earlier phases, screenshots and reports are never rewritten. Failure evidence + the original expected outcome survive into the bug report. | B · `lite:failure-evidence` | `results-and-evidence.md` `<result_organization>` |
| 12 | **Never mask a failure.** A failing TC stays FAIL until a newer successful execution proves otherwise; first-run and re-run are merged by script, history kept. | B · `lite:results-integrity` | `final-run.md` |
| 13 | **No secrets** in code, logs, chat, command lines, the learning file, records. Credentials by secret NAME from the project's env file. **Sign in once per role** by the recorded `auth` strategy (storageState / API helper); UI sign-in only in TCs about sign-in, or as the recorded fallback; `.auth/` git-ignored, removed at close-out. Overrides engine `code-craft.md` §15 (no `storageState`). | A · safety + B | `intake.md` |
| 14 | **Project knowledge first.** The constitution (if any) read once — its rules apply unless one weakens a gate (gate wins, Deviations); never edited. The learning file (if any): one index + tag grep before any question; an answer already on file is reused, never re-asked; every new fact written back as a generic tagged line — **facts about the app / environment only**; a workaround for a skill / tooling defect goes to Deviations + the return, never the learning file. Lite never creates either file. | stage 1 / 4 | `intake.md` `<project_learning_file>` |
| 15 | **Folders.** `lite init-run` derives `reports/{SPEC-x/}{US-…}` from the TC document's folder; screenshots and logs mirror it. Roots: flag → QA manifest → constitution → the project's Playwright config → default (init-run `sources`). | `lite init-run` | `results-and-evidence.md` |
| 16 | **Unhealthy environment ⇒ `ENVIRONMENT_BLOCKED`**, never blamed on the code under test. Missing required input ⇒ `BLOCKED`. | `lite preflight` | `execution.md` `<environment_gate>` |

**Checkpoint A (four checks)** — `lite:tsc` · `lite:pom` · `lite:traceability` · `lite:assertions`; execution-safety findings (focus-only, `networkidle`,
unbounded timeouts / disabled run protections, credentials) ride along: a provable violation FAILs the gate, an unprovable one is a warning.
**Checkpoint B (three checks)** — `lite:results-integrity` · `lite:tc-status-coverage` · `lite:failure-evidence`.
PASS is recorded by the script; FAIL / BLOCKED is repaired or reported — a required check is never bypassed.

**Not in Lite** (Full only): subagent delegation, the 58-item semantic review at A and B, `AWAITING_REVIEW` cycles, the 12-principle data-readiness
walk, `--parallel-shadow`, the open-question parking flow beyond one batch, repeated learning greps and preflights, the per-run delivery question.
