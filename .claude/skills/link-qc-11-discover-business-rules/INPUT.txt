SKILL: link-qc-11-discover-business-rules
WHAT IT DOES: Discovers the code behind a User Story, extracts every business rule the code
ENFORCES (field limits, formats, required fields, uniqueness of names/codes/IDs, defaults,
ranges, state transitions, permissions, duplicate handling, messages, locale differences) as
EARS statements with file:line evidence, compares them with the spec, and EXPORTS the rules
that exist in the code but not in the spec — with proposed requirement wording and suggested
test cases — as PROPOSALS for the Product Owner. Nothing is treated as fact (learning file,
REQ, skills 3/5) until the PO's decisions are recorded and --apply-approved is run.

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

DISCOVERY RUN — REQUIRED (one of):
  1. Story/requirement ID(s)   — e.g. US-1031475, or several IDs, or a feature name
  2. Path to a spec/story file — e.g. Testing/Requirements/US-.../REQ-*.md, specs/.../spec.md
                                 (a spec with several stories is SPLIT: one export per story)
  3. Free-text acceptance criteria pasted in the chat
  (No spec at all? Run it anyway — it exports the full rule catalogue instead of a gap list.)

APPROVAL RUN:
  --apply-approved <US-id>…   — after the QC and Product Owner filled the decision block
                                (Intended / Bug / Ignore per rule) in the export file

OPTIONAL FLAGS:
  --no-compare  — rule catalogue only, skip the spec comparison
  --reprofile   — rebuild the shared repository profile (Testing/White_Box_Testing/.project-profile.md)

ASKED DURING THE RUN (only if it cannot detect them):
  - Where to write the output, if Testing/Requirements/ does not exist in the project
    (A: create the standard layout · B: a folder you name). Remembered for next runs.
  - Which story, when the input is blank or ambiguous; confirmation of the split when the
    input holds more than one story.

NOTES:
  - Read-only on the codebase and on the spec/REQ files: it proposes a REQ delta, never applies it.
  - No URL or credentials needed — static code analysis, not live testing.
  - Reuses the repository profile built by skill 10; builds it the same way if missing.
  - Learning file: a discovery run writes ONLY your answers and a "pending PO approval"
    pointer. Rules are written only by --apply-approved, tagged "approved by PO {date}".

============================================================
OUTPUT — WHAT YOU GET
============================================================
  {requirements-root}/[SPEC-{spec-name}/]US-{id}-{name}/   (one folder PER STORY; default root
                                                   Testing/Requirements/; SPEC-{spec-name}/ only for
                                                   stories taken from a spec file — same as skill 2)
    US-{id}-code-rules.md        ← Status PENDING PO APPROVAL · A partially specified ·
                                   B NOT IN SPEC (main export) · C contradictions ·
                                   D in spec not in code · enforcement matrix (UI/server/DB) ·
                                   spec coverage · QC / PO decision block · proposed REQ delta
                                   → after --apply-approved: Status APPROVED + approved REQ delta
  {requirements-root}/[SPEC-{spec-name}/]CODE-RULES-SUMMARY.md  ← multi-story runs only: links + counts per story
  Testing/White_Box_Testing/.project-profile.md   ← created only if missing (shared with skill 10)
  Testing/project-learning.md                     ← discovery: Q&A + pending pointer only;
                                                     approval: approved rules, UI limits, test data

WHEN TO RUN: after skill 2 has produced the REQ file and before skill 3 designs test cases —
or any time you suspect the code enforces rules nobody wrote down. Flow: discovery run →
QC + PO fill the decision block → --apply-approved → skill 2 folds the approved delta into the
REQ → skill 3 test cases; Bug decisions and D-gaps → skill 10.
