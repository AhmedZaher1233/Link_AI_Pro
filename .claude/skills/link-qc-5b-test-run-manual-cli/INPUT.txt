SKILL: link-qc-5b-test-run-manual-cli
WHAT IT DOES: The manual twin of link-qc-5-test-run-automation. Takes skill 3's test case
document (Status: APPROVED proceeds at once; anything else is ONE question — approve now, run
without approval, or stop) and EXECUTES EVERY test case in it, in full and
separately, in the RUNNING application through the Playwright command line (playwright-cli) — a
real test run, not discovery: smoke first behind the 30% smoke gate (no self-heal), then
positive, then negative; PASS only after the expected result was positively observed; an
assertion-point screenshot per TC; a [HUMAN] step ends the TC "PARTIAL — human step pending".
Tests an AI chatbot / assistant whose reply differs every run: a TC that carries skill 3's optional
"AI Oracle" field is sent its prompt, the reply TEXT is read, the deterministic hard checks run,
then Claude judges the rubric per repeat against the TC's threshold; every reply is stored
verbatim. Writes ONLY skill 5's run report set (TEST-RUN-REPORT / BUG-REPORT markdown, the .runs
phase file, the rendered HTML page) into skill 5's story folder with the same phase counter and
bug numbering. It NEVER writes into the TC document, TEST-DATA, the review page or ADO-MAP.
Publishing (skill 4) is not required and never asked for.

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

  1. The TC document                       — a path to TEST-CASES-{feature}.md, OR a feature name /
                                             User Story ID (the skill finds the document under
                                             Testing/Manual_Test/TestCases/**/US-{id}-*/), OR a

                                             Per run, never remembered; a status is never flipped

PREREQUISITES (installed for you — the skill never installs anything itself):

                                             /link-qc-1-generate-update-testing-structure repair when you

                                             the skill stops BEFORE asking for anything (BLOCKED,

  - .playwright-cli/ in .gitignore         — added by the same sync step (snapshots land there).
  - OPTIONAL: a browser secrets file       — run skill 1's scripts/set-playwright-secrets.ps1 (or
                                             .sh) ONCE in your own terminal if you want unattended
                                             logins; it stores username / password pairs in a file

                                             at it. Name each pair after the account ID the TCs
                                             reference — A1_USER / A1_PASSWORD for "[A1]". The

OPTIONAL FLAGS:
  (no scope flag)                There is no scope gate and no sampling: every TC of the document
                                 is executed on every run. A narrowing flag or sentence gets one
                                 line ("this skill runs every TC") and the full run. For a
                                 narrowed live check use skill 3b.
  --approve | --unapproved       Answer the approval question in advance: --approve sets
                                 "Status: APPROVED" in the document, --unapproved runs it as it

                                 one of them is BLOCKED.
  --env <name>                   The environment name written into the report (UAT, staging…)
                                 when the learning file does not already record it.
  --audit                        Probe playwright-cli and analyse the document only: the entry
                                 gate, the set (stages, smoke, AI TCs with repeats / thresholds,
                                 human-step TCs, data-changing TCs), the plan line and what a
                                 run would write. Writes NOTHING, asks for nothing else.

ASKED DURING THE RUN — ONE message, after the playwright-cli probe:
  2. Application base URL                  — the TEST-DATA "[E1]" row; reused from the learning
                                             file when recorded there, otherwise asked (each

                                             Recorded in the report's Run bullets and the learning

  3. Username PER ACCOUNT the TCs reference — only when the TEST-DATA §1 row says "unknown"
  4. Login method PER ACCOUNT              — A) attended: the skill opens a visible browser for
                                             that account and asks you to log in yourself, then
                                             continues (works with SSO / MFA); or

  5. Is the story implemented?             — only when the document's header says

                                             SKIP — pending implementation, never defects
  6. Environment notes                     — e.g. VPN, test tenant, where the build number is
                                             shown, "this is production" (then no data changes)
  7. May this run change data on {env}?    — yes: test cases whose Data effect is creates /
                                             modifies / deletes are executed, records are
                                             identified before the change, reverted through the
                                             UI after the screenshot where a way exists, and
                                             listed at the end; no: those TCs are SKIP with the
                                             reason. The same "yes" lets the skill PREPARE a
                                             MISSING data item through the automation project's
                                             existing helper; a UI journey (a creating TC of the
                                             document, a known flow or a creation screen) is
                                             prepared without any answer — the message lists it.
                                             A MISSING item makes its TCs SKIP only when no way
                                             to create it exists, the state is not creatable
                                             (evidence recorded) or you declined.

ASKED ONCE BEFORE THE STAGE THAT NEEDS THE ITEM — only when such a way was found:
  7b. May the skill create {item} through     — the application's create endpoint read from the
      an endpoint found in the source code,      source code (no helper exists), or a database
      or write it in the database?               write for a state no API or UI can reach; one
                                                 message naming each item, what would be done
                                                 and the TCs it unblocks; yes per item; no →
                                                 those TCs SKIP (QC declined)

ASKED ONCE AFTER THE LAST STAGE — only when something was prepared:
  7c. Keep or clean up the prepared records  — every record this run created is listed with its
                                                 way and identity; default keep (recorded in the
                                                 learning file); "clean up D{n}" removes it
                                                 through an existing helper or the UI; anything

NOT ASKED (by design):
  - Scope                                  — every TC runs; the plan is stated in one line.
  - Revision authorization                 — never needed: the TC document is never written.
  - Heal / retry                           — never: a failure is a failure; a second attempt
                                             exists only after an environment failure.
  - Publishing to Azure DevOps             — never: that is skill 4, independent of this run.

IF ANYTHING ELSE IS UNCLEAR: the skill searches the learning file and previous answers first, then
asks with the gap, the affected TCs, the evidence, a recommended answer and its reason, the
alternatives and what stays pending — and never acts on an unanswered recommendation. An expected
result or an AI rubric line it cannot decide becomes a Q-{n} in the phase's Open questions and the
TC ends INCOMPLETE — never a guessed PASS or FAIL. Your confirmed answers (never credentials) are
saved under "Manual Run Model (skill 5b)".
