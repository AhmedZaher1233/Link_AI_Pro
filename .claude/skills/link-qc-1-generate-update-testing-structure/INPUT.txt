SKILL: link-qc-1-generate-update-testing-structure
WHAT IT DOES: Audits, repairs or restructures the project's QA foundation — the Testing/
layout, docs/steering/ (L1/L2/L3), Node/NPM + Playwright, .mcp.json (Playwright, Azure DevOps,
Docx MCP; optional Figma MCP), the optional playwright-cli for skill 3c and Python + Pillow for
link-qc-6-ui-testing, the QA skills 1-12, 3b and 3c (.claude/skills/), Testing/project-learning.md and
Testing/qa-manifest.json — with a read-only preflight first and a deterministic PASS/FAIL
validation at the end. Invoke it explicitly; other skills never run it for you.

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

REQUIRED:
  (nothing) — run it from the project root. The preflight script scans the project itself.

OPTIONAL ARGUMENT (existing projects; skips the mode question):
  audit        — Mode A: health-check only. Writes NOTHING (no downloads, installs, renames,
                 learning-file or manifest updates). Lists what B would fix.
  repair       — Mode B: sync skills 1-12, 3b and 3c + sync-skills command, add missing folders / steering
                 layers / MCP entries / learning-file sections, normalize names (steering files,
                 .claude/Skills → .claude/skills, legacy learning heading), write the manifest.
                 Never moves or rewrites existing valid content.
  restructure  — Mode C: everything in B plus a migration to the canonical layout, applied only
                 after you confirm the old → new move plan (git mv, nothing deleted).
  A brand-new project (no Testing/, no automation code) runs the full setup without asking.

ASKED DURING THE RUN (only if it cannot detect them and the learning file has no answer):
  1. Which mode (A/B/C) — existing projects without an argument
  2. Azure DevOps hosting + organization — for the azure-devops MCP entry. Detected from the git
     remote first: dev.azure.com / *.visualstudio.com → cloud (Microsoft's @azure-devops/mcp,
     organization name); any other host (a self-hosted Azure DevOps Server) → self-hosted
     (@tiberriver256/mcp-server-azure-devops, org URL https://host/Collection + project).
     No Azure DevOps remote → you are asked for a User Story URL, never for a guess.
  3. Confirmation of the move plan — Mode C only
  4. A source path for a missing L1/L2 steering document when the source repo has none —
     the skill NEVER writes L1 or L2 itself
  5. The Azure DevOps PAT — when the azure-devops MCP entry is written and the user-level
     variable it references (AZURE_DEVOPS_PAT_B64 for cloud, AZURE_DEVOPS_PAT for self-hosted)
     does not exist on this PC, the skill asks you to run scripts/set-azure-devops-pat.ps1 (or
     .sh) in YOUR OWN terminal. One hidden prompt stores the token in both forms (base64 for the
     cloud server, raw for the self-hosted one) as user environment variables and verifies them.
     The token never passes through the chat; the skill only checks that the variable exists.
     Afterwards FULLY QUIT VS Code (all windows) and relaunch it — a window reload or an /mcp
     reconnect keeps the old environment, and the validator will say "saved on this machine but
     missing from this session" until you do.
  5b. Replace the Link skills? — Mode B/C/new, when our skill folders are already present:
     the sync DELETES the Link QA skill folders (+ the /sync-skills command) and downloads fresh
     copies. Any enhancement you made to a Link skill is removed and replaced with the new version
     (the question lists every edited / extra file). Replace / Update only (keep my edits) / Cancel.
     Your own skills and every other file are never deleted. Asked every run, never recorded.
  6. Install the optional tools? (yes/no) — Mode B/C/new only, when something is missing:
     playwright-cli for skill 3c, and Pillow + numpy for link-qc-6-ui-testing's static-image annotation
     (only when a Python interpreter already exists — Python itself is never installed).
     Yes → the skills sync runs with --tools (global @playwright/cli, its chromium browser, the
     .playwright-cli/ line in .gitignore, pip install pillow numpy). No → nothing installed;
     3b and every other skill work as before, 3c will BLOCK until /sync-skills --tools runs,
     link-qc-6-ui-testing annotates live pages in the DOM without Python. Recorded, never re-asked.
     Optional afterwards, for unattended 3c logins only: run scripts/set-playwright-secrets.ps1
     (or .sh) in YOUR OWN terminal — the skill only checks that the file exists.
  7. Add the Figma MCP for link-qc-6-ui-testing? — only when you compare against Figma designs. It is Figma's
     remote server (https://mcp.figma.com/mcp); you log in once through /mcp — no token is ever
     written to a file. Without it, Figma links fall back to exported screenshots.
