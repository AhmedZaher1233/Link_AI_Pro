SKILL: 1-generate-update-testing-structure
WHAT IT DOES: Creates or repairs the project's testing environment — the Testing/ folder
structure, the docs/steering/ quality-authority documents (L1/L2/L3), Node/NPM + Playwright
setup, MCP servers (.mcp.json), and the QA skills (.claude/Skills/1-7 + sync-skills command).

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

REQUIRED:
  (nothing) — the skill scans the project itself. Just run it from the project root.

ASKED DURING THE RUN:
  0. RUN MODE — asked ONLY when the project already has a testing structure
     (Testing/ or automation code, or two of: playwright config, .mcp.json, QA skills,
     docs/steering/, project-learning.md). A brand-new project is never asked.
       A) Health-check only   — verify everything, change nothing, report what B would fix
       B) Update & repair     — pull latest skills, add missing steering/folders/MCP
                                entries, keep the current structure untouched
       C) Restructure         — migrate to the canonical Testing/ + docs/steering/ layout
                                after you confirm the old → new move plan (moves, no deletes)
     In EVERY mode, skills missing from .claude/Skills/ (and a missing sync-skills command)
     are downloaded from the source repo first — before this question is asked.

ASKED DURING THE RUN (only if it cannot detect them):
  1. Azure DevOps organization name        — for the azure-devops MCP entry
                                             (auto-detected from the git remote when possible)
  2. AZURE_DEVOPS_PAT_B64 environment var  — you set it yourself; value = base64(":" + PAT).
                                             The skill never asks for the raw token.

OPTIONAL:
  - A different automation folder name/location, if your project already has a convention.
  - A source path for the steering documents (L1 / L2 / L3), if they are not already in
    docs/steering/ and not available from the source repository. The skill NEVER writes
    L1 or L2 itself — a missing layer is reported, not invented.

============================================================
OUTPUT — WHAT YOU GET
============================================================
  Testing/
    project-learning.md    (shared knowledge base: Index + shared sections + one section per
                            skill; every skill reads it before asking you and updates it after)
    Requirements/          (per-User-Story folders are added later by skill 2)
    Manual_Test/TestCases/
    Automation/  (pages, tests, reports, screenshots, automation-logs)
    White_Box_Testing/
  docs/steering/
    README.md                       (index + resolution order — authored by this skill)
    L1-testing-foundation.md        (generic, org-wide — copied, never authored)
    L2-testing-qa-standards.md      (generic, cross-project — copied, never authored)
    L3-project-testing.md           (this project's config/SLAs — template, you fill it in)
  + non-canonical steering file names normalized (no spaces, no " 1"/" 2" suffixes) and all
    references updated, so skills 3, 5 and 6 can resolve them
  + Playwright installed & configured
  + .mcp.json with Playwright / Azure DevOps / Word MCP entries
  + validation report (PASS/FAIL per component, including Steering Docs)

WHEN TO RUN: once per project, or after environment drift — BEFORE skills 2–5.
RE-RUNNING on a configured project is safe: the skill asks for mode A / B / C first.
