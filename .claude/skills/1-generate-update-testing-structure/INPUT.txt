SKILL: 1-generate-update-testing-structure
WHAT IT DOES: Audits, repairs or restructures the project's QA foundation — the Testing/
layout, docs/steering/ (L1/L2/L3), Node/NPM + Playwright, .mcp.json (Playwright, Azure DevOps,
Word MCP), the QA skills 1-7 (.claude/skills/), Testing/project-learning.md and
Testing/qa-manifest.json — with a read-only preflight first and a deterministic PASS/FAIL
validation at the end. Invoke it explicitly; other skills never run it for you.

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

REQUIRED:
  (nothing) — run it from the project root. The preflight script scans the project itself.

OPTIONAL ARGUMENT (existing projects; skips the mode question):
  audit        — Mode A: health-check only. Writes NOTHING (no downloads, installs, renames,
                 learning-file or manifest updates). Lists what B would fix.
  repair       — Mode B: sync skills 1-7 + sync-skills command, add missing folders / steering
                 layers / MCP entries / learning-file sections, normalize names (steering files,
                 .claude/Skills → .claude/skills, legacy learning heading), write the manifest.
                 Never moves or rewrites existing valid content.
  restructure  — Mode C: everything in B plus a migration to the canonical layout, applied only
                 after you confirm the old → new move plan (git mv, nothing deleted).
  A brand-new project (no Testing/, no automation code) runs the full setup without asking.

ASKED DURING THE RUN (only if it cannot detect them and the learning file has no answer):
  1. Which mode (A/B/C) — existing projects without an argument
  2. Azure DevOps organization name — for the azure-devops MCP entry (git remote first)
  3. Confirmation of the move plan — Mode C only
  4. A source path for a missing L1/L2 steering document when the source repo has none —
     the skill NEVER writes L1 or L2 itself
  5. The Azure DevOps PAT — when the azure-devops MCP entry is written and the user-level
     variable AZURE_DEVOPS_PAT_B64 does not exist on this PC, the skill asks you to run
     scripts/set-azure-devops-pat.ps1 (or .sh) in YOUR OWN terminal. The script prompts for the
     token with hidden input, stores base64(":" + PAT) as a user environment variable, and
     verifies it. The token never passes through the chat; the skill only checks that the
     variable exists. Reopen the terminal / Claude Code afterwards.

============================================================
OUTPUT — WHAT YOU GET
============================================================
  Testing/
    project-learning.md      (shared knowledge base — created from the template if missing)
    qa-manifest.json         (paths, steering files, framework, deviations — read by skills 2-7)
    Requirements/  Manual_Test/TestCases/  Automation/{pages,tests,reports,screenshots,automation-logs}
    White_Box_Testing/
  docs/steering/
    README.md                (index + the single set of resolution rules — authored by this skill)
    L1-testing-foundation.md / L2-testing-qa-standards.md   (copied from the source repo, never authored)
    L3-project-testing.md    (template — you fill the placeholders)
  .claude/skills/1-7 + .claude/commands/sync-skills.md  (synced from the source repo)
  .mcp.json                  (Playwright / Azure DevOps / Word entries, env-var placeholder for the PAT)
  playwright.config.ts       (created only if missing)
  Validation table: Node.js · NPM · Playwright · Playwright cfg · Folder layout · Steering Docs ·
  L1/L2 generic · Learning File · .mcp.json · Playwright MCP · Azure DevOps MCP · Word MCP ·
  QA Skills · Skills current · sync-skills cmd · Manifest — each PASS / WARN / FAIL / NOT_RUN,
  never PASS without the check having run.
  Mode A adds "Would be fixed by B" and "Needs C" lists and changes nothing.

WHEN TO RUN: once per project BEFORE skills 2-7; again (audit first) whenever the setup drifts.
