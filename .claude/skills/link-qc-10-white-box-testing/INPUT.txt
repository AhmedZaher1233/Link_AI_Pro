SKILL: link-qc-10-white-box-testing
WHAT IT DOES: Audits the CODEBASE against a requirement — traces where/how it is
implemented, finds gaps, potential bugs, and concrete reproduction scenarios.
(First run auto-profiles the repository and caches the profile.)

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

REQUIRED (one of):
  1. Story/requirement ID      — e.g. US-1031475, or a feature name
  2. Path to a spec/story file — e.g. Testing/Requirements/US-.../REQ-*.md, specs/.../spec.md
  3. Free-text acceptance criteria pasted in the chat

OPTIONAL FLAG:
  --reprofile   — force a fresh repository profile (use after big structural changes)

NOTES:
  - Read-only on the codebase: it never modifies source code.
  - No URL or credentials needed — this is static code analysis, not live testing.
  - Checks Testing/project-learning.md before asking which requirement to analyse; what it
    learns about the system (rules, where checks happen, bug patterns) is written back there
    in plain language under "White-Box Model".

============================================================
OUTPUT — WHAT YOU GET
============================================================
  Testing/White_Box_Testing/                 (root = paths.whiteBox from qa-manifest.json)
    .project-profile.md                     ← cached repo profile (reused next runs, shared with skill 11)
    SPEC-{spec-name}/                       ← when the REQ sits under Requirements/SPEC-{spec-name}/
      US-{id}-{name}/                       ←   (or the requirement came from a spec file)
        {RequirementID}-{Feature}-analysis.md   ← gaps, bugs, repro scenarios, verdict
    US-{id}-{name}/                         ← REQ directly under Requirements/, ADO story, free text
      {RequirementID}-{Feature}-analysis.md
  The report folder mirrors the story's folder under Testing/Requirements/ exactly (same
  layout skill 3 uses for TCs). Older flat reports at the root are read as context only.
  Testing/project-learning.md               ← updated: system rules learned, module map, Q&A

WHEN TO RUN: any time you need "is this story actually implemented, and where are the
bugs?" — typically before or alongside skill 3.
