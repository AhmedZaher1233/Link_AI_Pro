SKILL: 6-test-run-automation
WHAT IT DOES: Takes the HUMAN-APPROVED TC document that skill 5 has ALREADY published to
Azure DevOps → generates Playwright automation (POM mandatory) → measures static coverage →
resolves test-data readiness with you → runs smoke-gated staged execution (smoke → positive →
negative) with live progress + ETA in the chat → produces the phase HTML report + bug report →
closes the loop in DevOps (Custom.TestAutomated on the work items skill 5 created).
It does NOT beautify or publish TCs — that is 5-publish-test-cases-azure.

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

REQUIRED:
  1. Approved TC document path   — Testing/Manual_Test/TestCases/[SPEC-{spec-name}/]{Story}/TEST-CASES-*.md
                                   MUST contain "Status: APPROVED" (skill refuses anything
                                   else — it never flips the status itself)
  2. User Story ID or EXACT title — the Azure DevOps work item the TCs belong to

ENTRY GATE (checked, not asked): skill 5 must have run on THIS version of the document —
  {Story}/ADO-MAP.md and TEST-CASES-*-beautified.md exist and carry the same source hash as
  the approved document. Missing or stale → BLOCKED with "run 5-publish-test-cases-azure first".

OPTIONAL:
  3. Environment                 — target test environment (defaults to the automation
                                   project's TEST_ENV preset)
  4. --workers N                 — browser windows for the parallel group (default 3;
                                   serial groups always run with 1)
  5. --headless                  — hide the browser (default: VISIBLE, you watch the run)

HOW IT RUNS: the skill builds a run plan from your TCs — read-only TCs run in parallel,
TCs that create/edit/delete or share the same data run one after another (you can steer
this with the optional "Data effect" / "Shared data" fields from skill 3) — then runs
smoke → positive → negative with the browser visible.

BEFORE ASKING: the skill searches Testing/project-learning.md (Automation Model + Automation
Tricks) for the environment, run settings, known elements and past environment fixes. Only
what is missing is asked, and your answers are saved there. PATs are never written to it.

PREREQUISITES (asked/checked, not guessed):
  - Azure DevOps MCP connected with a read/write PAT (Work Items + Test Management) — needed
    for the close-out; on 401/403 the skill asks you to reconnect the MCP server
  - Healthy app environment (URL responding, VPN up) — otherwise the run stops as
    ENVIRONMENT_BLOCKED
  - Test data: BEFORE the run the skill checks every TC's preconditions/data against the
    environment, lists the TCs that would be skipped, and asks you ONCE per gap how to
    handle it — api (an endpoint it found) / ui (an end-to-end setup journey) / db (only if
    you name the env var holding the connection string) / manual (you insert, reply "done")
    / skip. Created data is deleted after the run unless you add "keep".

============================================================
OUTPUT — WHAT YOU GET
============================================================
  {automation_root}/reports/US-{id}/phase-N.json + phase-N.html   ← run of record
                                                                    (history never overwritten)
  {automation_root}/automation-logs/US-{id}/run-progress-{stamp}.log  ← live tailable log
  {automation_root}/screenshots/{UserStoryName}/{TC-ID}.png            ← EVERY TC, taken at the
                                                  ASSERTION POINT (before any data cleanup)
                                                  {TC-ID}-failed.png   ← failed TCs only
                                                  (same names each run → re-run REPLACES them)
  {automation_root}/reports/US-{id}/run-plan.json                      ← parallel/serial groups
  {automation_root}/reports/US-{id}/data-readiness.json                ← test-data gaps + your decisions
  {automation_root}/reports/US-{id}/coverage/                          ← static coverage dashboard + CSVs
  {automation_root}/playwright.us-{id}.config.ts                       ← per-story config (headed)
  Azure DevOps: Custom.TestAutomated + automated-test metadata on the TC work items,
                summary comment on the story; {Story}/ADO-MAP.md updated with the final status
  + live progress in the chat (counts, current TC, elapsed, estimated remaining)
  Testing/project-learning.md  ← updated: automation tricks, element identification, env fixes, Q&A

WHEN TO RUN: last — after a human set Status: APPROVED on skill 3's output AND skill 5
published it to Azure DevOps.
