SKILL: 3-generate-manual-test-cases
WHAT IT DOES: Designs complete manual test cases (EN + AR) from the requirement, validates
them against the LIVE application via Playwright MCP, and delivers a markdown TC document
plus an HTML review page for HUMAN approval.

============================================================
INPUT — WHAT YOU MUST PROVIDE
============================================================

ALWAYS REQUIRED:
  1. Feature name / User Story ID          — what to design TCs for

PICK YOUR STARTING POINT (tell the skill which case applies):
  Case 1 — Manual TCs already exist:
      → give the TC source: file path, Azure DevOps test cases, Word document, or paste
        the TCs as text. The skill updates/normalizes them instead of starting over.
  Case 2 — No TCs and no spec file:
      → give the Azure DevOps story ID (or Word doc path). The skill retrieves the story,
        writes REQ-{id}.md into Testing/Requirements/US-{id}-{name}/, and designs from it.
  Default — Spec/requirement file exists, no TCs:
      → give the spec path, or let the skill find it
        (Testing/Requirements/**/REQ-*.md, docs/specs/).

ASKED DURING THE RUN (before any live validation):
  2. Application base URL                  — reused from Testing/project-learning.md when
                                             recorded there; otherwise asked
  3. Username + password PER ROLE          — exact accounts used in the TC steps
                                             (ALWAYS asked fresh; never stored in the file)
  4. Is the story implemented?             — implemented / partially / not implemented /
                                             not sure (skill verifies live either way)

OPTIONAL:
  - Learning file path                     — default Testing/project-learning.md (shared
                                             knowledge base created by skill 1)

IF ANYTHING IS MISSING: the skill searches Testing/project-learning.md first, then asks you
in ONE message and WAITS. It never assumes. Your answers are saved to the file's
"Manual TC Model" section so they are not asked again.

============================================================
OUTPUT — WHAT YOU GET
============================================================
  Testing/Manual_Test/TestCases/{UserStoryName}/
    TEST-CASES-{feature}.md   ← source of truth (Status: PENDING HUMAN REVIEW)
    TC-REVIEW-{feature}.html  ← visual review page
  Testing/project-learning.md ← updated: flows, UI behaviour, test data, EN/AR notes, Q&A

YOUR NEXT STEP: review, adjust Smoke / Automation Candidate markings, optionally fill the
"Data effect" (read-only / creates / modifies / deletes) and "Shared data" fields on TCs
that change or share data (skill 6 uses them to decide parallel vs one-after-another
execution; blank = it infers), then set Status: APPROVED in the markdown — that unlocks
skill 5 (publish to Azure DevOps) and then skill 6 (automation).
